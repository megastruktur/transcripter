# Profiles — контракт формата (host ≥ 0.9.0)

Профиль — это YAML-файл в этом каталоге: «если у записи есть тег X — суммируй
этим промптом и назови артефакт так-то». Профили перечитываются при каждом
запуске стадии — рестарт сервера НЕ нужен. Невалидный профиль логируется
(warn) и пропускается; сервер и остальные профили продолжают работать.

## Формат (волна A)

```yaml
id: my-profile                # обязательно; уникальный slug [a-z0-9-]
version: 1.0.0                # обязательно; semver версии ПРОФИЛЯ
min_host_version: 0.9.0       # обязательно; хост ниже — профиль пропускается (warn)
display_name: My Profile      # обязательно
description: Что делает профиль  # обязательно; кавычки, если есть двоеточие
tags: [mytag, другой тег]     # обязательно, непустой; match-any, exact,
                              # case-insensitive (теги записей нормализуются
                              # в lowercase)
summarize:
  prompt: |                   # обязательно; ОБЯЗАН содержать {transcript}
    Ты — … «{title}» …        # {title} — опционально
    {transcript}
  output_artifact: my-notes.md  # опционально; default summary.md;
                                # только [a-z0-9._-]
```

## Семантика

- **Матч**: у записи есть хотя бы один тег из `tags` профиля → профиль
  применяется. Совпало несколько профилей → выигрывает первый по
  алфавиту `id` (в логе warn).
- **Промпт**: после подстановки `{title}`/`{transcript}` весь текст уходит
  одним user-сообщением в LLM суммаризации. Без профиля используется
  встроенный промпт — поведение прежнее.
- **Артефакт**: саммари всегда пишется в `meta/summary.md`; при экспорте в
  Obsidian-папку записи файл получает имя `output_artifact`.
- **Применение**: профиль матчится на момент запуска стадии. Смена тегов на
  существующей записи → нажмите regenerate summarize.

## Секция enrich (host ≥ 0.9.0, нужен compose-профиль `graph`)

```yaml
enrich:
  prompt: |              # обязательно; ОБЯЗАН содержать {transcript}
    Извлеки из транскрипта JSON: {"events": [...], "entities": [...],
    "relations": [...]} … {transcript}
  node_labels:           # опционально; defaults: Entity / Event
    entity: Entity
    event: Event
```

После summarize хост просит LLM вернуть JSON-объект
`{events: [{ts, kind, summary}], entities: [{slug, label, type}],
relations: [{from_slug, to_slug, type}]}` и пишет его в Neo4j: узлы и рёбра
несут `tag` и `origin_recording_id`; повторный прогон идемпотентен
(DETACH DELETE по записи → MERGE по (tag, slug)); дедуп — slug-нормализация
+ LLM-вопрос «тот же объект?». Промпт подставляет ТОЛЬКО `{title}` и
`{transcript}` (литерально) — фигурные скобки JSON-примеров безопасны.
Стадия best-effort: без графа или enrich-секции — skipped, ошибка не портит
запись.

## Будущие секции (forward-compat)
